# Feedback Loop — How the System Learns

> The goal: every workflow output gets tracked, measured, and fed back into skill improvement. **Zero manual data entry.**

## The Loop (One Cycle)

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   OUTPUT    │───▶│   PUBLISH   │───▶│  COLLECT    │───▶│   ANALYZE   │
│  (agent)    │    │  (send it)  │    │  (metrics)  │    │  (win/loss) │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                              │
                          ┌─────────────────────────────────────┘
                          ▼
                   ┌─────────────┐    ┌─────────────┐
                   │   UPDATE    │───▶│  NEXT CYCLE │
                   │  (skills)   │    │  (improved) │
                   └─────────────┘    └─────────────┘
```

## 1. Output Tracking (Automatic)

Every time an agent produces output, a log entry is created:

| Field | Source | Automation |
|-------|--------|------------|
| `output_id` | UUID generated by agent | ✅ Auto |
| `agent_name` | Agent that produced it | ✅ Auto |
| `skill_used` | Which skill was invoked | ✅ Auto |
| `timestamp` | When it was produced | ✅ Auto |
| `content_hash` | SHA256 of output text | ✅ Auto |
| `variant` | A/B test variant (A/B/n) | ✅ Auto if experiment active |
| `context` | Brief context (task, goal) | ✅ Auto from prompt |

**Where stored:** `agent-swarm/learning/logs/YYYY-MM/outputs.jsonl` (append-only, one line per output)

**No manual entry.** The orchestration layer (or agent itself) appends to this file after every workflow run.

## 2. Metrics Collection (Semi-Automatic)

Metrics are pulled from external tools, not entered by hand:

| Metric Source | How to Pull | Frequency |
|---------------|-------------|-----------|
| **Email (Klaviyo/Outlook)** | API query for open/reply/click rates | Daily batch |
| **LinkedIn** | Buffer analytics API or manual screenshot | Weekly |
| **Notion** | Query databases for task completion, action taken | Weekly |
| **Shopify** | API for conversion, revenue, AOV | Daily batch |
| **Airtable** | API for lead status changes, outreach outcomes | Weekly |
| **Colin's Feedback** | Slack/message reaction or quick reply | Ad-hoc |

**The Rule:** If a metric can't be pulled automatically, it gets a 5-second manual capture (e.g., screenshot, quick reply, emoji reaction). No spreadsheets.

## 3. Win/Loss Log

After metrics are collected, outcomes are classified:

```json
{
  "output_id": "uuid-from-outputs-log",
  "agent": "outreach_sequencer",
  "skill": "email-sequence",
  "variant": "A",
  "outcome": "win",
  "win_reason": "reply_received_and_meeting_booked",
  "metrics": {
    "open_rate": 0.42,
    "reply_rate": 0.08,
    "meeting_booked": true
  },
  "timestamp": "2026-07-15T10:00:00Z",
  "notes": "Subject line: 'Quick question about [Company]' — personalized with company name"
}
```

**Loss example:**
```json
{
  "output_id": "uuid",
  "agent": "outreach_sequencer",
  "skill": "email-sequence",
  "variant": "B",
  "outcome": "loss",
  "loss_reason": "no_reply_after_7_days",
  "metrics": {
    "open_rate": 0.28,
    "reply_rate": 0.00
  },
  "timestamp": "2026-07-15T10:00:00Z",
  "notes": "Subject line: 'Partnership opportunity' — too generic, spam-filtered"
}
```

**Where stored:** `agent-swarm/learning/logs/YYYY-MM/win-loss.jsonl`

## 4. Pattern Extraction (Monthly, Automated)

At the end of each month, the system:

1. **Reads** all `win-loss.jsonl` entries for the month
2. **Groups** by skill and variant
3. **Identifies** patterns in wins vs. losses
4. **Outputs** a `patterns-report.md` with:
   - Winning patterns (what to keep doing)
   - Losing patterns (what to stop doing)
   - New hypotheses (what to test next)

**Pattern extraction is automated analysis, not manual review.** The agent reads the logs and writes the report. Colin reviews the report (5 minutes), approves or rejects recommendations.

## 5. Skill Update (Monthly, Conditional)

Skills are only updated when:

- **Minimum evidence:** 10+ win/loss entries for a skill variant
- **Clear signal:** Win rate difference ≥ 20% between variants
- **Colin approves:** No automatic skill updates without approval

**Update process:**
1. Agent proposes skill changes based on patterns report
2. Colin reviews (5 minutes) — approve / reject / modify
3. Agent applies changes to skill file
4. Agent commits to git with descriptive message
5. Agent updates skill version in metadata

## 6. Monthly Review (Capped at 30 Minutes)

See [MONTHLY_REVIEW.md](MONTHLY_REVIEW.md) for the full cadence. The review is:

- **Data:** Pulled automatically by agent before the meeting
- **Questions:** Pre-loaded, Colin answers yes/no or 1-5 scale
- **Decisions:** Agent drafts recommendations, Colin approves
- **Actions:** Agent executes approved changes

## Automation Rules

| Task | Who Does It | How Often |
|------|-------------|-----------|
| Output logging | Agent (auto) | Every workflow run |
| Metrics pulling | Agent (API) | Daily batch |
| Win/loss classification | Agent (auto) | When outcome known |
| Pattern extraction | Agent (monthly) | Last day of month |
| Report generation | Agent (monthly) | Last day of month |
| Skill update | Agent (after Colin approves) | Monthly or as needed |
| Git commit | Agent (after Colin approves) | After each update |

## Colin's Manual Touch Points (Total: ~30 min/month)

1. **Review pattern report** (10 min) — last day of month
2. **Approve skill changes** (5 min) — approve/reject/modify proposals
3. **Answer 3-5 quick questions** (10 min) — what worked, what didn't, what to test
4. **Review agent roster** (5 min) — add/remove agents based on ROI

**Everything else is automated.**

## Key Principles

1. **Track everything, analyze monthly.** Don't let perfect be the enemy of good. Log every output, review once a month.
2. **Only update when there's signal.** 10+ data points and 20% win rate difference minimum. No tinkering based on n=2.
3. **Colin approves all skill changes.** The system recommends, Colin decides. No autonomous skill mutations.
4. **A/B test one thing at a time.** See [A_B_TESTING.md](A_B_TESTING.md).
5. **If it takes more time than it saves, kill it.** The learning system is a tool, not a job. If monthly review becomes a burden, simplify.

## Quick Start

To bootstrap the feedback loop:

1. ✅ Create `agent-swarm/learning/logs/YYYY-MM/` directories (auto-created on first write)
2. ✅ Ensure every agent appends to `outputs.jsonl` after each run
3. ✅ Set up daily metric pull (Buffer API, Klaviyo API, etc.)
4. ✅ First monthly review: 2026-07-31
